# Argument Construction Framework

## Purpose

This framework defines the missing bridge between:

- **TH / EV / Idea Bank** = what to think about
- **WF / WT / WQ / WP** = what form to write and how to execute it

No new lesson IDs are created. E001–E234 remains the fixed corpus.

The central problem is not generating more ideas. It is converting one useful idea into a coherent argument under time pressure.

---

# 1. Six argument functions

These are **functions**, not a mandatory six-sentence template.

## ARG01 — Answer / Position｜問いへの直接回答

**Question:** What am I actually claiming?

The first sentence or planning note should answer the prompt directly.

Examples:
- I think X should...
- Option B should be prioritized...
- X can be useful, but...
- The main reason is not A alone; B also matters.

Failure mode:
- background explanation without an answer
- criteria listed without a decision
- a summary of the source instead of a response

This is governed first by **WQ00 Task fulfillment**.

---

## ARG02 — Reason｜判断理由

**Question:** Why should the reader accept that position?

A reason is an evaluative or causal proposition, not merely another opinion.

Typical sources:
- EV01–EV10 evaluation criteria
- a retrieved canonical Idea
- a TH operation that reveals a relevant difference

Examples:
- because it improves access
- because the cost is concentrated on one group
- because the policy changes incentives
- because the evidence does not justify a strong causal claim

Failure mode:
- “I think X is good because it is useful.”
- several unrelated reasons with no development

---

## ARG03 — Mechanism｜なぜその理由が成り立つか

**Question:** How does the reason produce the claimed effect?

This is the most important bridge between “having an idea” and “having an argument.”

Typical forms:
- X changes Y, which then affects Z.
- The policy reduces a barrier by...
- A default changes behavior because...
- Redundancy helps because independent capacity remains when one component fails.

Mechanism may be:
- causal
- behavioral
- institutional
- distributional
- evidential

Failure mode:
- jumping from reason to conclusion with no intermediate explanation
- writing “therefore” where the causal link is still unstated

Related systems:
- TH01 Cause & Mechanism
- TH05 Behavior & Incentives
- TH06 Implementation & Safeguards
- D04 cause → effect
- D03 problem → solution

---

## ARG04 — Support｜具体化・証拠・例

**Question:** What makes the reason concrete enough to understand or trust?

Support can be:
- a concrete example
- source evidence
- a comparison
- a short scenario
- a relevant observation from the prompt

An example is not decorative. It should instantiate ARG02–ARG03.

Good:
> Lack of sleep reduces concentration. For example, a student who studies until 2 a.m. may spend the next day rereading material without retaining it.

Weak:
> For example, many students have problems.

Failure mode:
- an example that introduces a different reason
- invented statistics
- copying source details without connecting them to the claim

Related systems:
- D02 general → specific
- D09 example → generalization
- RQ / source evidence where appropriate

---

## ARG05 — Qualification｜条件・限界・反対要素

**Question:** When does my claim stop being true, become weaker, or require a condition?

Qualification includes:
- concession
- limitation
- safeguard
- uncertainty
- exception
- trade-off
- scope restriction

Examples:
- However, this does not mean...
- This approach works only if...
- The evidence suggests X, but it does not prove Y.
- The policy may help some groups while burdening others.

Failure mode:
- adding “however” without changing the scope of the claim
- treating qualification as indecision
- saying both sides without returning to a judgment

Related systems:
- TH02 Trade-off
- TH06 Implementation
- TH08 Uncertainty
- TH09 Governance
- D05 concession → main claim
- D10 exception → qualification
- WQ03 Precise

---

## ARG06 — Return / Decision｜問いへ戻す

**Question:** Given the reason, mechanism, support, and limits, what follows?

This may be:
- a conclusion
- recommendation
- priority choice
- conditional approval
- calibrated causal/evidential statement

It should not merely repeat ARG01 word for word.

Examples:
- Therefore, universities should use online classes selectively rather than replace all in-person teaching.
- For these reasons, Option B deserves priority despite its slightly higher cost.
- The results support further testing, not the conclusion that the intervention is already proven effective.

Failure mode:
- ending with the example
- leaving the trade-off unresolved
- introducing a new reason in the final sentence

---

# 2. The core conversion

The learner-facing mental routine is:

> **Idea → Reason → Mechanism → Support → Qualification → Answer**

But the actual writing process begins with Task fulfillment:

> **Prompt → Answer → strongest Reason → Mechanism → Support → Qualification as needed → Return**

This distinction matters.

TH / EV / Idea Bank generate candidates.  
The learner should **select**, not dump, those candidates.

A strong 100-word answer often develops:
- one position
- one main reason
- one mechanism
- one example
- one useful qualification

rather than two or three undeveloped reasons.

# 3. Connection to TH / EV / Idea Bank

## TH tells the learner what reasoning operation to run

Examples:

- TH02 Trade-off
  - generates competing benefit/cost
  - ARG02 chooses the decisive reason
  - ARG05 carries the counter-cost

- TH03 Distribution
  - ARG02: average improvement is insufficient
  - ARG03: benefits differ by subgroup
  - ARG04: identify a subgroup/scenario
  - ARG06: target or modify the policy

- TH07 Evidence
  - ARG02: evidence does not support the strong claim
  - ARG03: explain selection / proxy / confounding / measurement issue
  - ARG05: calibrate the scope
  - ARG06: state the narrower justified conclusion

## EV supplies the criterion for ARG02

Example:
- EV01 Access → “because it reduces a participation barrier”
- EV05 Fairness → “because the burden falls disproportionately on...”
- EV09 Resilience → “because the system retains capacity after disruption”

An EV word alone is not a reason.

Weak:
> This is better because of fairness.

Strong:
> This is fairer because students who face the largest access barriers receive additional support rather than the same resources as students who already have good access.

## Idea Bank supplies a reusable proposition

Example:
- IDEA0028 efficiency ≠ resilience

Converted:
- ARG01: Keep some reserve capacity.
- ARG02: maximizing normal-time efficiency can make the system fragile.
- ARG03: if all capacity is already committed, a small disruption creates a shortage.
- ARG04: backup transport / hospital beds / power supply.
- ARG05: reserve capacity has a cost.
- ARG06: retain limited independent backup where failure is high-consequence.

# 4. WF mappings

The six functions are rearranged by writing type.

| WF | Existing type | Recommended argument route |
|---|---|---|
| WF01 | opinion / reason | ARG01 → ARG02 → ARG03 → ARG04 → (ARG05) → ARG06 |
| WF02 | comparison / trade-off | criterion → compare A/B → decisive ARG02 → ARG05 trade-off → ARG06 |
| WF03 | cause / effect | causal claim → ARG03 chain → evidence/support → ARG05 boundary → calibrated conclusion |
| WF04 | proposal / solution | problem → proposal → ARG03 mechanism → ARG05 limitation/mitigation → test → ARG06 |
| WF05 | evaluation / priority | criteria → evaluation → trade-off → choice → ARG06 |
| WF06 | source-linked transfer | source principle → target answer → ARG03 mapping → ARG04 support → ARG05 scope → ARG06 |
| WF07 | summary-linked | select → compress → preserve relation; argument functions apply only if an evaluative extension is required |

Do not force ARG04 or ARG05 where the task does not need them.

# 5. Phase progression already present in E001–E234

## P1 — reason language and basic relation

P1 frequently teaches:
- comparison
- cause/effect
- one reason
- safe claim strength

The argument bridge exists, but it is often embedded inside language retrieval and short writing.

Example:
- E004 transfers causal language into a new topic.
- E015 asks the learner to compare normal times and disruption.

P1 should remain light. Do not retrofit a six-step planning sheet into early lessons.

## P2 — explicit construction begins

P2 already contains highly explicit argument construction.

Examples:
- E087: claim → reason → qualification → action
- E092: problem → proposal → mechanism → limitation/mitigation
- E093: criteria → evaluation → choice

This is the natural phase for the learner to recognize the common structure.

## P3 — mechanism, evidence, and qualification deepen

P3 develops:
- multi-step causal chains
- evidence constraints
- concession
- conditional judgment
- source integration

Examples:
- E117: cause → primary effect → behavior change → secondary effect
- E119: concede usefulness → reject overclaim → retain qualified policy claim

This is where ARG03 and ARG05 become central.

## P4 — compression under exam conditions

P4 reduces scaffolding.

Example:
- E208 explicitly requires position → reason → concrete example.
- later full sets require the same construction under 120-minute total-task pressure.

The learner should no longer run a long checklist. The internal compressed routine is:

> **Answer → Why → How → Example → Limit? → Finish**

# 6. Planning rule for 80–120 words

Default:

1. **Answer the question**
2. choose **one strongest reason**
3. write the **mechanism in one sentence**
4. add **one concrete support**
5. add a qualification only if it improves accuracy or judgment
6. return to the decision

Planning time target in exam transfer:
- about 60–90 seconds once the routine is established

Do not:
- brainstorm five reasons
- write two unrelated examples
- force both sides
- force every ARG function
- invent evidence

---

# 7. Example

Prompt:
> Should universities replace most in-person lectures with online classes?

Idea candidates:
- access
- quality
- flexibility
- cost

Selection:
- main reason = access
- main limitation = quality for discussion/practical work

Argument:

**ARG01 Answer**  
Universities should use more online classes, but they should not replace most in-person teaching.

**ARG02 Reason**  
Online classes can improve access.

**ARG03 Mechanism**  
Students who live far from campus or have schedule constraints can attend without travel.

**ARG04 Support**  
For example, recorded or live online lectures can help a student who has a long commute.

**ARG05 Qualification**  
However, discussion and practical courses may lose quality online.

**ARG06 Return**  
Universities should therefore use online teaching selectively.

The learner does not need to label these six sentences during the exam.

# 8. Audit finding

The existing curriculum already teaches most of this architecture, but under different local names.

Representative evidence:
- E087: claim / reason / qualification / action
- E092: problem / proposal / mechanism / limitation
- E093: criteria / evaluation / choice
- E117: explicit multi-step causal mechanism
- E119: concession → qualified claim
- E208: position / reason / concrete example

Therefore the content gap is **not missing lessons**.

The gap is:
1. these patterns are not yet explicitly unified as one curriculum-wide argument-construction system,
2. metadata tracks WF and discourse forms separately, so the bridge from Idea/TH/EV to paragraph functions is hard to audit,
3. early P1 writing should remain light, while P2 should become the point where the common structure is named.

---

# 9. Revision policy

Do not mass-edit E001–E234.

Next review should identify only:
- a small number of P2 bridge lessons where the common argument routine should be named once,
- a small number of P3 lessons where ARG03 / ARG05 should be explicitly connected back to that routine,
- P4 planning instructions that can use the compressed five-question routine without increasing task time.

No new lesson IDs.
No new Idea Bank records solely for paragraph structure.
No mandatory six-sentence template.
