# Explanation & Reasoning Policy

## Purpose

E001–E234の教材数は固定する。新しい問題・新しいE IDを増やすのではなく、既存教材の**解説と考え方の再現性**を高める。

この教材の解説の目的は、単に模範解答を理解・暗記できることではない。

> **似ていない別問題でも、同じ考え方を自力で再現できること**

を最終基準とする。

## Current priority

現在のcontent workの最優先は、E001–E234の**解説・思考過程の充実**。

- 新規E ID: 作らない
- 新規問題バンク: 作らない
- 速度訓練用の新問: 作らない
- 語彙頻出リスト / Core Vocabulary整備: 後回し
- 既存教材の解説、思考経路、模範解答の読み方、転用可能性を優先する

## Core principle

解説は「答え」ではなく、次の流れを学習者が再現できるようにする。

> 問いを読む → 判断の核心を掴む → 観点を選ぶ → 理由を選ぶ → mechanismを作る → supportを置く → 英語にする

TH / EV / Idea / ARGはこの流れを設計する内部フレームとして使う。

コード名を毎回暗記させること自体は目的ではない。

---

## Explanation language

学習者向けの**思考過程・根拠説明・自己修正・持ち帰りは原則として日本語中心**にする。

英語のまま残すもの:
- Reading / Passage 本文
- 設問文
- 選択肢
- model answer / answer example
- 語法・構文そのものを説明対象にするときの英語表現
- 根拠として必要な短い本文引用

日本語中心にするもの:
- なぜその答えになるか
- どこを根拠に読むか
- どういう順序で考えるか
- 誤答がなぜ弱いか
- 自己修正の観点
- 次の問題へ持ち越す思考ルール

目的は英語を避けることではない。
**英語を読む負荷と、解説を理解する負荷を不必要に重ねないこと**を優先する。

特に、本文読解そのものが学習対象の教材では、
> 英語の本文・設問 → 日本語で思考を整理 → 必要な英語表現を確認
の順にする。

解説を英語で書く教育的理由がある場合だけ例外とし、その理由が明確でない限り英語だけの解説にしない。

# Standard 6-part explanation structure

自由英作文・論証系教材では、原則として以下の6要素を解説に持たせる。
教材形式によって不要な要素は簡略化してよいが、**思考経路が飛ばないこと**を優先する。

## 1. この問題で考えること

テーマの要約ではなく、**判断の核心**を1–2文で示す。

Bad:
- AIについて考える
- 環境問題について考える

Good:
- AIが便利かではなく、どこまで自動化し、どこに人間の判断を残すべきかを考える
- 環境に良いかではなく、便益と導入コストをどう比較するかを考える

問い:
- 何を決める問題か
- 何を比較する問題か
- どの条件が結論を変えるか

## 2. 考え方

ここを解説の中心とする。

答えを先に置くだけでなく、原則として次の一本道を見せる。

> 問い → 判断基準 → 理由 → mechanism → 結論

必要に応じて:
- trade-off
- subgroup / distribution
- evidence limitation
- implementation condition
- uncertainty
- alternative design

を途中に入れる。

重要なのは、**ReasonとConclusionの間をmechanismでつなぐこと**。

### Example pattern

> AIは処理を速くできる  
> → ただし誤りが重大な結果につながる場面がある  
> → 完全自動化すると誤りを止める人がいなくなる  
> → したがって高リスク領域では人間の確認を残すべき

### 観点を自力で作る手順

解説で完成した分類・観点だけを提示しない。
学習者が**その観点へどう到達するか**を示す。

抽象語（access / safety / fairness / effectiveness など）を分解するときは、原則として次の順で考える。

1. **抽象語を見つける**
   - 何が曖昧な一語に圧縮されているかを見る

2. **成立条件を問う**
   - 「それが本当に成り立つには、何が必要か」と考える

3. **単一対策後にも残る失敗ケースを作る**
   - 「これを改善しても、まだうまくいかないのはどんな場合か」と問う
   - ここで残った障壁が、新しい観点の候補になる

4. **失敗原因を観点へ抽象化する**
   - 個別例をそのまま覚えず、複数の例に使える条件名へまとめる

例:
> 医師を増やす  
> → それでも遠くて行けない  
> → それでも必要な専門診療がない  
> → それでも人材が定着しない  
> → access は staffing だけでなく reachability / service availability / continuity に分けられる

重要なのは、**分類を暗記させることではなく、「対策しても残る失敗」を探して成立条件を逆算する思考操作を再現可能にすること**。

## 3. 弱い考え方との比較

ありがちな浅い答案を示し、**何が不足しているか**を明示する。

典型的な弱点:
- 「便利」「重要」「良い」などの抽象語だけで終わる
- 理由と結論の間が飛んでいる
- メリットを列挙するだけ
- exampleが別の理由になっている
- 対象者・条件・例外を考えていない
- evidenceが示す以上のことを断言する

推奨形式:

> × 弱い考え方  
> ○ 一段深めた考え方  
> なぜ改善したか

例:

> × AIは便利だから使うべき  
> ○ AIが定型処理を代替すれば、人間は複雑な判断に時間を使える  
> → 「便利」を具体的なmechanismに変えている

## 4. 答案の組み立て

問題に即してARGを具体化する。

- **Position / Answer**: 立場・直接の答え
- **Reason**: 主理由
- **Mechanism**: なぜその理由が結論につながるか
- **Support**: 具体例・状況・結果
- **Qualification**: 必要な条件・例外
- **Return / Decision**: 結論へ戻す

全要素を毎回答案に明示的に入れる必要はない。
ただし、解説では**どの機能がどこにあるか**を追えるようにする。

## 5. 模範解答の読み方

模範解答を「正解文」として置くだけにしない。

可能な範囲で:
- Position
- Reason
- Mechanism
- Support
- Qualification
- Return

の役割を示す。

説明対象:
- 各文が何の仕事をしているか
- because / therefore / for example等が論理上何をつないでいるか
- 具体例が主理由をどう支えているか
- 条件表現が断言をどう調整しているか
- なぜ別の言い方よりこの表現が安全・自然なのか

模範解答は**暗記対象ではなく、論証構造の見本**として扱う。

## 6. 次の問題に持っていくもの

最後に、今回の内容を1つ以上の**再利用可能な思考ルール**へ圧縮する。

例:

> 技術導入では「使う / 使わない」だけでなく、  
> **どの仕事を任せ、どこに人間の判断を残すか**と考える

転用先は必要に応じて2–4個程度示す。

例:
- AI診断
- 自動運転
- 機械翻訳
- 採用支援

この部分の目的は題材知識の横展開ではなく、**思考操作のtransfer**。

# Relationship to existing systems

## TH / EV

TH / EVは「今回使ったラベル」を貼るだけでは不十分。

解説では必要に応じて:
- なぜこのTHが有効か
- どのEVを判断基準として優先したか
- 別のTH / EVを使うと結論やargumentがどう変わるか

を説明する。

## Idea Bank

Ideaは丸暗記させる結論ではなく、別題材に転用できるpropositionとして扱う。

## ARG

解説の中心はARG、とくに:

> Reason → Mechanism → Support

の接続。

「理由を思いつく」だけで終わらず、**理由を論証へ変換する過程**を明示する。

## Writing / language

英語表現の説明は、思考が決まった後に接続する。

単語・表現を羅列するのではなく:
- この論理関係をどう英語化するか
- どの構文なら安全に表現できるか
- どの語がどの目的語と結びつくか

を優先する。

Core Vocabulary / 頻出語の体系化は別タスクとして後回し。

---

# Depth rule

全E001–E234を一律に長文化しない。

既存教材を監査して、必要な箇所だけ増強する。

優先して直す教材:
- 模範解答はあるが考え方が飛んでいる
- Reasonはあるがmechanismが弱い
- Post-solveがテーマ知識に留まりtransferが弱い
- 弱い答案との比較がない
- 模範解答の構造が読めない
- TH / EV / Ideaがラベルだけで終わっている
- 英語表現の説明が論理とつながっていない

十分な教材は無理に長くしない。

---

# Explanation QA gate

解説改訂時は次を確認する。

1. 問題の核心がテーマ名ではなく判断課題として示されているか
2. Reason → Mechanism → Conclusionのつながりが追えるか
3. 完成した観点を提示するだけでなく、学習者がその観点へ到達する手順を追えるか
4. 必要ならSupport / Qualificationまで示されているか
5. 弱い考え方が「なぜ弱いか」まで説明されているか
6. 模範解答の各文の機能を説明できるか
7. 今回固有の内容を別問題へ転用可能な形に圧縮しているか
8. TH / EV / Idea / ARGが単なるラベル付けになっていないか
9. 不要に長文化していないか
10. 思考過程・根拠説明が不必要に英語だけになっていないか
11. 新規問題・新規E IDを追加していないか

## Pass criterion

最終的な合格基準:

> **解説を読んだ学習者が、模範解答の再生ではなく、別題材で同じ思考回路を使えるか**

これを満たすようにE001–E234を選択的に改訂する。
